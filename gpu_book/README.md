# GPU 学习笔记（写作计划）

边学 GPU，边整理成一本书。整本书围绕一个问题展开：**一个超级大的矩阵乘法，怎样才能算得快？**

## 为什么以矩阵乘法为主线

GPU 擅长的是大规模数据并行和高吞吐。矩阵乘法特别适合 GPU，原因在于它的计算量是 O(n³)，数据量却只有 O(n²)，同一份数据会被反复使用，计算单元可以持续工作。相比之下，向量加法这类逐元素运算虽然也能并行，但速度被内存带宽限制，GPU 的优势并不明显。

因此，这本书真正要回答的问题是：**怎样让计算单元不等数据**。把一个矩阵乘法从最朴素的版本一步步优化到接近 cuBLAS，几乎会用到 GPU 的全部核心概念：并行模型、内存层次、访存合并、shared memory、寄存器分块、Tensor Core。算术强度（arithmetic intensity）和 roofline 模型会尽早引入，作为解释每一步优化的统一工具。

## 写作原则

- **一条基准贯穿全书**：第一章就建立 benchmark，学会计算 FLOPS。之后每章都用同一套基准测量，并记录“当前达到硬件峰值的百分比”，让进步看得见。
- **硬件知识按需引入**：不集中、抽象地讲硬件。先写出代码，测量后发现慢，再问为什么慢，此时引出对应的硬件概念。
- **正文用 Markdown，配图用 drawio。**
- **术语加粗并给出英文**：术语在全书第一次出现时加粗，并在括号里给出英文，如**算术强度**（Arithmetic Intensity）。之后再出现用普通文字，只在正式定义它的地方可以再加粗一次。本身就是英文的词（如 BLAS、GEMM）不必重复；列表开头只起标签作用的小标题不算术语。
- **术语用中文还是英文**：译名通行、没有歧义、读起来自然的用中文，如缓存、共享内存、全局内存、寄存器、缓存行，首次出现时在括号里给出英文。在代码、API或工具输出里原样出现、读者需要拿去搜索、中文译名又不够通行的保留英文，如kernel、warp、block、occupancy、sector，首次出现时提一句常见的中文译名。各级缓存在第2章定义后简称L1、L2、L3。
- **少用“不是X，而是Y”**：不要先摆出一个读者本来不会有的想法再去否定它（如“从来不是……而是……”），直接正面陈述。X 是读者真实会有的疑问时可以用。
