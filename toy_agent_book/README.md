# 自己动手写智能体

Build a Toy Coding Agent from Scratch

> 写作计划，书名待定。工作草稿，随讨论随时改。

## 想法

平时用Coding Agent很多，大致也知道它是怎么工作的：一个循环，模型说要调什么工具，程序就去调，结果再交回给模型。但“大致知道”和“亲手写过”差得很远。就像toy系列的前两本：知道Transformer长什么样，不等于能写出一个推理引擎。所以这本书还是同一个办法，自己从零写一个玩具版的Coding Agent，一点一点来，每一步都看得见、跑得通。

市面上讲“从零写Agent”的材料已经不少（见[research.md](research.md)），这本书仍然按自己的思路写一遍。它和别的材料最大的不同，是能从模型内部往外讲：读过第一本的人知道模型只会预测下一个token，那工具调用、上下文窗口、prompt caching在token层面到底是怎么回事，这本书可以讲到底。

## 和前两本的关系

这个系列的第一本《自己动手写LLM推理引擎》讲模型怎么跑，第二本《自己动手训练LLM》讲模型怎么训。这一本讲模型怎么用：给模型配上工具和循环，让它替人干活。三本书合起来，正好是一个模型从“训出来”到“跑起来”再到“干起活来”的全过程。

这本书不要求读过前两本。读过的话，第二章的对话模板和采样参数、第三章流式输出里的prefill和decode、第四章工具调用的token细节、第十三章的prompt caching会读得更有体会。

## 写作原则

* **一章一个概念。** 第一章就给出一个能干活的循环，之后每章往上加一样东西：工具调用、权限、压缩、检索、MCP、Skills……每加一样都能跑，都能和上一章比。
* **先有问题，再有部件。** 不直接介绍“MCP是什么”，而是先让Agent碰到一个解决不了的问题，再引出对应的设计。
* **不用框架，少用SDK。** 能用标准库和HTTP请求写的，就不引入LangChain之类的框架。框架把循环藏起来了，而循环正是这本书要讲的东西。
* **API和界面也要拆开看。** LLM API和终端界面都是读者天天碰、却很少细看的东西。API不用SDK，直接看HTTP请求、SSE事件和各家协议的差别；界面不用TUI框架，从ANSI转义序列写起，一直写到差分渲染。框架留到最后再对照。
* **对照真实设计。** 每章结尾对照Claude Code、Codex、Pi、mini-swe-agent在同一个问题上的选择。区分官方公开的事实和外部的源码分析、推测。
* **能对答案的就对答案。** 模型的输出是随机的，没法逐位比对。退一步，用录好的回复回放来测试循环本身，再用一组自建的小题算通过率，看每一章的改动有没有用。
* **正文用Markdown，配图用drawio。** 风格和toy系列前两本保持一致。

## 技术选择（待定）

下面几项还没定，先记下倾向：

* **语言：** Python，和前两本一致，uv管理。
* **模型接口：** 倾向于用OpenAI兼容的Chat Completions协议，同一份代码既能连云端的大模型，也能连本地的Qwen3（llama.cpp、Ollama、vLLM都提供这个接口）。要不要同时支持Anthropic的Messages接口，待定。
* **模型：** 日常开发和跑题集用云端模型，Agent的效果才有保证。云端模型已定为DeepSeek V4 Flash，走DeepSeek API的OpenAI兼容接口（`https://api.deepseek.com`），模型名待用`/models`接口确认。讲工具调用的token细节时，用本地的小模型（Qwen3），因为只有本地模型能看到完整的对话模板和原始输出。作者的机器是2019款Intel MacBook Pro，本地跑大一点的模型会很慢，需要实测。
* **代码组织：** 沿用第一本的做法，`code/book/chNN/`每章一个自包含的目录，每章在上一章的基础上改。
