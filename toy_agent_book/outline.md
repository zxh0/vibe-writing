# 大纲

> 工作草稿，随讨论随时改。

全书只做一件事：从一个几十行的循环开始，一章加一样东西，最后得到一个能在终端里读代码、改代码、跑测试的编程助手，也就是一个玩具版的Claude Code。

全书分五部分。第一部分让Agent跑起来，能干活，其中用三章把LLM API讲透；第二部分给它做一个像样的终端界面，从终端的工作原理讲到差分渲染；第三部分处理上下文，让它在大项目和长任务里不迷路；第四部分讲扩展，把MCP、Skills、子代理这些概念一个个亲手实现；第五部分跳出代码，讲怎么评估一个Agent，再对照几个真实的Agent，看它们的设计取舍。

每章的结构大致固定：先提出一个问题（Agent哪里不够用），再写代码解决它，跑一遍看效果，最后对照Claude Code、Codex、Pi、mini-swe-agent在同一个问题上的选择。

## 第一部分　跑起来

### 第1章　Agent就是一个循环

* 1.1 从用Coding Agent说起：我们每天看到的是什么，背后发生了什么
* 1.2 定义：“An LLM agent runs tools in a loop to achieve a goal”，逐词拆开
* 1.3 最小的Agent：一个`while`循环加一个`bash`工具，几十行，先让它修好一个真实的bug
* 1.4 模型和Harness：模型负责想，Harness负责其他一切；本书写的就是Harness
* 1.5 路线图：这个几十行的循环缺什么，后面每章补一样，画成一张图
* 对照：mini-swe-agent只有bash一个工具，照样能在SWE-bench上拿高分
* 配图：Agent循环；全书路线图

### 第2章　LLM API：一次请求

* 2.1 不用SDK：用标准库发一个HTTP请求，把请求和响应原样打印出来
* 2.2 消息列表：system、user、assistant三种角色；模型没有记忆，每次都把整段对话发回去
* 2.3 从消息到token：服务器用对话模板把消息列表拼成一段文本，再分词（接第一本的分词一章）
* 2.4 请求里的参数：`max_tokens`、`temperature`、`top_p`、`stop`，各自对应第一本采样一章的哪一步
* 2.5 响应里有什么：生成的内容、停止原因（说完了、到上限了、要调工具）、用量统计
* 2.6 计费和上限：输入token、输出token、缓存token分别怎么算钱；上下文窗口；对话越长越贵、越慢
* 动手：一个最简单的命令行聊天程序，每轮打印token用量和花了多少钱
* 配图：消息列表变成token序列；一次请求的往返

### 第3章　LLM API：流式输出

* 3.1 为什么要流式：一次完整的回复要等十几秒，用户等不了
* 3.2 SSE协议：HTTP响应不关闭，服务器一行一行地推`data:`事件
* 3.3 把碎片拼回来：文本是一段一段来的，工具调用的参数JSON也是一段一段来的
* 3.4 两个延迟：首个token的延迟和每秒token数，分别对应第一本里的prefill和decode
* 3.5 中途取消：用户不想等了，怎么断开连接，已经收到的部分怎么处理
* 动手：把第二章的聊天程序改成流式，测一测首token延迟和每秒token数
* 配图：SSE事件流；碎片拼接成完整消息

### 第4章　工具调用

* 4.1 让模型“做事”：模型只能输出文本，怎样让它执行命令
* 4.2 土办法：约定一种格式，从回复里解析命令（mini-swe-agent就这么做）
* 4.3 正式办法：用JSON Schema描述工具，模型返回结构化的调用请求
* 4.4 拆到token：工具定义被对话模板拼进了提示词哪里，模型又是怎样“说出”一段工具调用的（用Qwen3的对话模板，接第一本第十三章）
* 4.5 结果怎么回去：工具结果作为一条消息追加到对话里，再调一次模型
* 4.6 一轮里调多个工具，以及工具出错时怎么告诉模型
* 动手：把第一章的循环改成正式的工具调用，对比两种办法
* 配图：一次工具调用的完整往返；工具调用在token序列里的样子

### 第5章　LLM API：各家的协议

* 5.1 三套主流协议：OpenAI的Chat Completions和Responses，Anthropic的Messages
* 5.2 逐项对比：system放在哪、内容是字符串还是分块、工具调用和结果的格式、流式事件的种类
* 5.3 有状态还是无状态：Responses可以由服务器保存对话，Chat Completions和Messages每次都要发全量，各有什么好处
* 5.4 思考（reasoning）：思考的内容怎么返回、要不要发回去、怎么计费
* 5.5 本地模型：llama.cpp、Ollama、vLLM都提供OpenAI兼容的接口；“兼容”到底兼容到什么程度
* 5.6 写一个薄适配层：让Agent的其余部分不关心底下是哪家的模型
* 5.7 出错了怎么办：限流、超时、服务器过载，重试和退避
* 对照：Claude Code只说Messages，Codex只说Responses，Pi自己做了一层统一的多厂商接口；网关（OpenRouter、LiteLLM）在中间做翻译
* 配图：同一轮对话在三种协议里的样子

### 第6章　编程工具

* 6.1 一个Coding Agent需要哪些工具：读、写、改、跑命令、找文件、搜内容
* 6.2 读文件：带行号，太长就分段读
* 6.3 改文件：整文件重写、行号替换、字符串替换、diff，为什么主流都选了字符串替换
* 6.4 跑命令：超时、输出截断、工作目录、后台任务
* 6.5 找文件和搜内容：glob和grep
* 6.6 工具描述怎么写：描述就是给模型看的文档，写法直接影响效果
* 对照：Pi只有四个工具；Claude Code十几个；工具多一点好还是少一点好
* 配图：字符串替换编辑的几种失败情况

### 第7章　权限和沙箱

* 7.1 Agent会`rm -rf`吗：一个能执行任意命令的程序有多危险
* 7.2 每次都问：确认机制，以及它为什么让人烦
* 7.3 规则：允许列表、拒绝列表，命令怎么匹配
* 7.4 沙箱：把Agent关在一个目录、一个容器里
* 7.5 提示词注入：网页、文件、工具结果里的指令为什么不能听
* 对照：Claude Code的权限模式、Codex的沙箱、Pi的“全交给用户”
* 配图：一次工具调用经过的检查关卡

## 第二部分　终端界面

### 第8章　终端是怎么工作的

* 8.1 为什么Coding Agent都选了终端：离代码、命令、git最近，哪里都能跑
* 8.2 从电传打字机说起：tty、伪终端（pty）、终端模拟器和shell各管什么
* 8.3 输出：ANSI转义序列，颜色、粗体、移动光标、清除一行
* 8.4 输入：行缓冲模式和raw模式；方向键、Ctrl+C这些按键到底是什么字节
* 8.5 窗口大小和改变窗口时的信号；主屏幕和备用屏幕
* 8.6 一些现代扩展：括号粘贴、同步输出、超链接
* 动手：不用任何库，写一个会转圈的等待动画，再写一个能左右移动光标的输入框
* 配图：键盘、终端模拟器、pty、程序之间的数据流

### 第9章　动手写一个TUI

* 9.1 从`print`到界面：Agent的输出一边流式增长，一边还要有输入框、状态栏
* 9.2 一种简单的架构：状态决定画面，画面算出来再写到终端
* 9.3 全量重绘为什么闪：每次都清屏再画，用户会看到中间状态
* 9.4 差分渲染：和上一帧比，只重写变化的行；再用同步输出让一帧原子地出现
* 9.5 内联还是全屏：内容留在终端的滚动历史里，还是占满一屏自己管理滚动
* 9.6 输入框：多行编辑、历史记录、粘贴大段文本
* 9.7 显示Agent的内容：流式的Markdown、代码高亮、文件改动的diff、折叠过长的工具输出
* 9.8 中断：Esc和Ctrl+C分别停在哪里，怎样和第三章的取消接起来
* 动手：给Agent做一个差分渲染的界面，替换第一部分的`print`
* 对照：Pi的差分渲染；Claude Code早期的闪烁问题
* 配图：差分渲染前后两帧的对比；界面的分区

### 第10章　TUI框架

* 10.1 几种主流思路：声明式的组件树、Elm式的消息循环、每帧重画的立即模式
* 10.2 Python里的选择：Rich、Textual、prompt_toolkit，各自适合做什么
* 10.3 别的语言：Ink（React搬进终端）、Bubble Tea（Go）、ratatui（Rust）
* 10.4 真实Agent的选择：Claude Code用React渲染终端，Codex用Rust重写，Pi自己写了一个小框架；各自换来了什么、付出了什么
* 10.5 自己写还是用框架：本书的toy agent为什么自己写
* 配图：三种框架思路的对比

## 第三部分　上下文

### 第11章　提示词、记忆和会话

* 11.1 系统提示词里写什么：身份、环境、工具使用的规矩
* 11.2 一千token还是一万token：Pi和Claude Code的两种主张
* 11.3 项目记忆：`AGENTS.md`、`CLAUDE.md`这类文件，Agent启动时怎么读进来
* 11.4 跨会话记忆：让Agent记住用户的偏好
* 11.5 会话的保存和恢复：把对话存成文件，下次接着聊
* 动手：给Agent加上项目记忆和会话恢复，看它在同一个任务上的表现变化

### 第12章　上下文工程

* 12.1 上下文窗口是有限的：长任务跑着跑着就满了
* 12.2 塞满会怎样：越长越慢、越贵，也越容易忘事
* 12.3 压缩（compact）：让模型把前面的对话总结一遍，换掉原文
* 12.4 裁剪：哪些工具结果可以丢，哪些必须留
* 12.5 Prompt caching：为什么前缀不能乱改（接第一本的KV缓存一章，这是同一件事在服务器上的样子）
* 12.6 把目标拉回眼前：Manus的`todo.md`
* 对照：Claude Code的自动压缩、Codex的压缩、Manus把KV缓存命中率当头号指标
* 配图：上下文窗口随轮次的增长；压缩前后的对话；前缀缓存命中与失效

### 第13章　检索：RAG还是grep

* 13.1 项目太大，塞不进上下文：Agent怎么找到相关代码
* 13.2 RAG：切块、嵌入、向量检索，先亲手做一个
* 13.3 agentic search：让模型自己用grep、glob、读文件一步步找
* 13.4 两种办法在同一组问题上比一比
* 13.5 为什么Claude Code放弃了向量数据库，以及什么时候RAG仍然更好
* 配图：RAG的流程；agentic search的几轮查找

### 第14章　规划和待办

* 14.1 大任务一步做不完：先拆再做
* 14.2 待办工具：让模型自己维护一个任务列表
* 14.3 计划模式：先只读不改，出一份计划给用户确认
* 14.4 ReAct和Plan-and-Solve：学术界的说法和工程上的做法
