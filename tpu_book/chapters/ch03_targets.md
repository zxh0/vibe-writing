# 第 3 章　设计目标与衡量标准

> 本章要回答的问题：一颗芯片"好"的标准是什么？我们的第一颗芯片要定下哪些目标？

## 本章目标

- 会从硬件参数算出峰值算力和带宽
- 会用 roofline 判断一个负载在一颗芯片上是计算受限还是访存受限
- 为"我们的芯片"写下第一版设计目标

## 小节

### 3.1 峰值算力

- 峰值 = MAC 数 × 频率 × 2
- 以 CPU、GPU 为例代入计算
- 峰值与实际：利用率才是关键

### 3.2 内存带宽与算术强度

- 算术强度 = 运算次数 / 访存字节数
- 矩阵乘法的算术强度随矩阵变大而增长
- batch 对算术强度的影响：权重复用 batch 次

### 3.3 Roofline 模型

- 斜线（访存受限）与平台（计算受限），拐点的含义
- 与 gpu_book 第 3 章使用同一套画法
- 同一个模型在不同芯片上落在哪里

### 3.4 真正要优化的指标

- 每瓦性能：数据中心的电费和散热
- 每美元性能：总拥有成本（TCO）
- 延迟上限：推理服务的 SLO（比如第 99 百分位延迟），它限制了 batch 大小
- 为什么"峰值 TOPS"会误导

### 3.5 第一版设计目标

- 只做推理，不做训练
- 8 位整数乘法，32 位累加
- 延迟优先，而不是吞吐优先
- 做成协处理器，插在服务器的 PCIe 槽上
- 时间紧：设计要简单，宁可少做也不要做错

## 实验

- 画出一颗 CPU 和一颗 GPU 的 roofline，标出第 1 章三个模型的位置
- 在不同 batch 下重新计算 MLP 的算术强度，观察它在 roofline 上怎样移动
