# 第 8 章　喂饱阵列：片上存储

> 本章要回答的问题：256×256 的阵列每一拍都要吃数据。这些数据存在哪里、从哪里来，才能让阵列不空等？

## 本章目标

- 会算出阵列需要的输入带宽，并与 DRAM 带宽比较
- 理解软件管理的片上存储（scratchpad）与 cache 的区别
- 理解双缓冲和预取如何隐藏访存延迟
- 能用 roofline 解释第一代芯片的瓶颈

## 小节

### 8.1 算一算

- 256×256 阵列，每拍从左侧进入 256 个 int8 输入
- 换 WS 权重时，一次要装 64K 个 int8 权重
- 与 DRAM 带宽对比：输入必须来自片上，权重的复用决定能否跟上

### 8.2 Unified Buffer

- 一大块 SRAM，存放每一层的输入和输出激活值
- 一层的输出直接留在片上，作为下一层的输入，不回 DRAM
- 容量怎么定：要装下一个 batch 的中间结果

### 8.3 Weight FIFO

- 权重从片外 DRAM 流进来，排队等待装进阵列
- 权重只读、顺序访问：适合用 FIFO 而不是随机访问的存储

### 8.4 双缓冲

- 阵列里同时放两套权重：一套在算，一套在装
- 只要算一块的时间 ≥ 装一块的时间，权重装载就被完全隐藏
- 这个条件和 batch 大小的关系

### 8.5 为什么不用 cache

- 神经网络的访问模式完全可预测，编译期就能确定
- cache 需要标签、替换策略、一致性，占面积还带来不确定的延迟
- 软件管理存储：面积省、延迟确定，代价是编译器要更聪明（第 15 章）

### 8.6 第一代芯片的瓶颈

- 片外是 DDR3，带宽有限（v1 论文给出的数字写正文时核对）
- MLP 和 LSTM 在 batch 受延迟约束时算术强度低，落在 roofline 的斜线上
- CNN 复用高，能接近峰值
- 这件事直接推动了第二代改用 HBM（第 13 章）

## 实验

- 给模拟器加上 Unified Buffer、Weight FIFO 和一个限定带宽的 DRAM 模型
- 分别跑 MLP、CNN、LSTM，统计阵列空等的周期占比
- 改变 DRAM 带宽和 batch，观察瓶颈怎样转移
