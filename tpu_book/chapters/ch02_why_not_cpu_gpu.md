# 第 2 章　CPU 和 GPU 为什么不够好

> 本章要回答的问题：已经有 CPU 和 GPU 了，为什么还要造一颗新芯片？一次运算的能量到底花在了哪里？

## 本章目标

- 理解"计算便宜、搬运贵"这个事实，并能用能耗数据说明
- 理解 CPU、GPU 各自的设计取舍，以及它们对矩阵乘法意味着什么
- 理解领域专用架构（DSA）的基本思路

## 小节

### 2.1 一道算术题

- TPU 的立项背景：如果语音识别等神经网络服务被大规模使用，数据中心的算力需求会成倍增长（具体说法写正文时核对 v1 论文和 Google 公开报道）
- 两条路：买更多 CPU/GPU，或者造一颗效率高一个数量级的芯片
- 这件事的时间约束：从立项到部署只有大约 15 个月

### 2.2 一次运算的能量去了哪里

- 一条指令的生命：取指、译码、读寄存器、执行、写回
- 真正做乘加的那一步，只占整条指令能量的一小部分
- 参考 Horowitz（ISSCC 2014）的 45nm 能耗表：整数加法、浮点乘法、SRAM 读取、DRAM 读取的量级对比

### 2.3 片外访存的代价

- 读一次 DRAM 比做一次 8 位乘法贵几个数量级
- 结论：芯片设计的核心任务不是"多放乘法器"，而是"让每一份取出的数据被用很多次"

### 2.4 CPU 的取舍

- 大缓存、乱序执行、分支预测、复杂的控制：为单线程低延迟服务
- SIMD 能提高一些吞吐，但每条指令的控制开销仍在
- 对矩阵乘法：大部分面积在做与乘加无关的事

### 2.5 GPU 的取舍

- 海量简单核心、SIMT、大寄存器堆：为吞吐服务
- 仍然是通用可编程处理器：寄存器堆、线程调度、cache 的开销
- Tensor Core 是 GPU 对矩阵乘法的回应（与 gpu_book 第 13 章呼应）
- 对 2015 年的推理场景：延迟约束下 batch 不能太大，GPU 的吞吐优势打折

### 2.6 领域专用架构

- 只做一类事，去掉一切不必要的东西
- 用简单换效率：没有 cache、没有分支预测、没有多线程
- 代价：灵活性下降，必须押对负载

## 实验

- 用能耗表估算：在 CPU 上算一次 256×256 矩阵乘，取指和访存的能量占多少
- 对比一个假想的"只有乘法器和 SRAM"的芯片，能量能省多少
