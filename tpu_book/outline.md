# 大纲

全书假装我们是一个从零开始的芯片团队，目标是**做一颗专门算神经网络的芯片**。全书分五部分。第一部分弄清楚要算什么、现有芯片为什么不够好，并定下设计目标；第二部分从一个乘加单元出发，推导出脉动阵列；第三部分给阵列配上存储、控制和指令，拼出一颗类似 TPU v1 的推理芯片；第四部分为了支持训练，引入 bfloat16、HBM、向量单元和编译器，走到 TPU v2/v3；第五部分从一颗芯片扩展到上万颗，一直讲到今天的 Ironwood。

每章的结构大致固定：先提出一个**设计问题**，再给出读者自己可能想到的几种方案并算账，接着用模拟器做实验，最后**对照 Google 的选择**，区分"已公开的事实"和"本书的推测"。

全书有一个逐周期（cycle-level）的 Python 模拟器，随章节不断长大。从第 4 章的单个 PE 开始，到第 11 章变成一颗能跑 MLP 推理的完整芯片，到第 14 章加上向量单元能跑训练，到第 16 章能模拟多芯片通信。每个阶段都用同一组矩阵乘法和小模型测量，记录"阵列利用率"和"达到峰值的百分比"，作用相当于 gpu_book 里那张基准表。

本文件是全书的总览。各章更细的大纲（目标、小节要点、实验、配图、对照 Google）见 [chapters/](chapters/) 目录，以各章文件为准。正文写作时，标注"核对"的事实和数字都要回到论文或官方文档确认。

## 第一部分　问题：为什么要造一颗新芯片

### [第 1 章　神经网络到底在算什么](chapters/ch01_workload.md)

- 1.1 从一个全连接层说起：y = Wx + b，本质是矩阵乘法
- 1.2 卷积、注意力、LSTM：换个形状，仍然是矩阵乘法
- 1.3 数一数计算量：一个 MLP、一个 CNN、一个 Transformer 各有多少次乘加，矩阵乘法占多大比例
- 1.4 推理和训练的区别：推理只走前向，训练还要反向传播和更新权重，计算量大约是三倍
- 1.5 低精度够不够用：推理用 8 位整数为什么误差不大
- 设计问题：如果只把矩阵乘法做到极致，能覆盖多少工作量
- 实验：用 NumPy 统计几个典型模型里各类算子的 FLOPs 占比
- 配图：一个神经网络拆成矩阵乘法的示意

### [第 2 章　CPU 和 GPU 为什么不够好](chapters/ch02_why_not_cpu_gpu.md)

- 2.1 2013 年的那道算术题：如果每个用户每天用几分钟语音搜索，Google 需要把数据中心扩大一倍（TPU 立项的背景）
- 2.2 一次运算的能量去了哪里：乘加本身很便宜，取指、译码、寄存器读写和访存才是大头
- 2.3 片外访存的代价：读一次 DRAM 的能量是做一次 8 位乘法的几千倍
- 2.4 CPU 的取舍：为降低延迟做了大缓存、乱序执行和分支预测，这些对矩阵乘法几乎没用
- 2.5 GPU 的取舍：吞吐高了很多，但仍然是通用处理器，要为图形和通用计算付出代价
- 2.6 专用架构的思路：去掉一切不必要的东西，把面积和能量都留给乘加
- 设计问题：一颗芯片的面积和功耗预算，应该怎样分配
- 配图：一次运算的能量构成（参考 Horowitz 的能耗数据）、CPU/GPU/专用芯片的面积分配对比

### [第 3 章　设计目标与衡量标准](chapters/ch03_targets.md)

- 3.1 峰值算力：乘加单元数 × 频率 × 2
- 3.2 内存带宽和算术强度
- 3.3 Roofline 模型：同一个模型在不同芯片上落在哪里（与 gpu_book 第 3 章同一套语言）
- 3.4 真正要优化的指标：每瓦性能、每美元性能、延迟上限（推理有 SLO），而不只是峰值
- 3.5 为"我们的芯片"定下第一版目标：只做推理、8 位整数、延迟优先、一年内上线
- 设计问题：一个指标都不能放过，还是先抓最关键的一个
- 配图：roofline 上标出 MLP、CNN、LSTM 的位置

## 第二部分　计算核心：从一个乘加单元到脉动阵列

### [第 4 章　乘加单元](chapters/ch04_mac.md)

- 4.1 一个 MAC 由什么组成：乘法器、加法器、累加寄存器
- 4.2 整数与浮点：浮点乘法器为什么大得多
- 4.3 位宽的代价：乘法器面积大约随位宽的平方增长，8 位比 32 位小一个数量级
- 4.4 累加要更宽：8 位乘 8 位得 16 位，累加多次需要 32 位，否则会溢出
- 4.5 量化入门：把浮点权重映射到 int8，scale 与 zero point
- 设计问题：同样的面积，能放多少个 int8 MAC，多少个 fp32 MAC
- 实验：模拟器的第一块积木，写一个 PE 类，验证 int8 乘加和溢出行为
- 配图：MAC 的电路结构、不同位宽乘法器的面积对比

### [第 5 章　把乘加单元排起来](chapters/ch05_systolic.md)

- 5.1 最直接的方案：一万个 MAC 并排放，每个都从存储里取数据，带宽立刻爆掉
- 5.2 广播方案：一份数据同时送给一行 MAC，长导线带来的延迟和功耗
- 5.3 只和邻居说话：数据在相邻 PE 之间一拍一拍传递，这就是脉动阵列（H. T. Kung，1982）
- 5.4 走一遍 2×2 和 4×4 的例子：数据怎样错开进入、结果怎样流出
- 5.5 填充与排空：阵列启动和结束时的空转，以及它对小矩阵的影响
- 设计问题：怎样让一份从存储里取出的数据被尽量多的 MAC 使用
- 实验：用模拟器逐周期跑一个 4×4 脉动阵列，打印每一拍每个 PE 的状态，与 NumPy 结果比对
- 配图：广播与脉动的对比、4×4 阵列的数据流动时序图

### [第 6 章　数据流：谁站着不动](chapters/ch06_dataflow.md)

- 6.1 矩阵乘法里的三份数据：权重、输入、部分和，哪一份留在 PE 里
- 6.2 Weight stationary：权重预先装进阵列，输入流过、部分和向下累加
- 6.3 Output stationary：部分和留在 PE 里，权重和输入都流动
- 6.4 Input stationary 与 row stationary（Eyeriss）
- 6.5 复用分析：每种数据流下，每份数据被用了多少次，访存次数和能耗各是多少（参考 Sze 等人的分类）
- 6.6 为什么 TPU 选 weight stationary：推理时同一份权重会被一整个 batch 反复使用
- 设计问题：给定一个模型和 batch 大小，哪种数据流最省能量
- 实验：在模拟器里实现 WS 和 OS 两种阵列，统计各自的访存次数
- 配图：四种数据流的示意、复用次数对比表

### [第 7 章　阵列多大才合适](chapters/ch07_array_size.md)

- 7.1 越大越好吗：算力随边长平方增长，但填充排空的开销和浪费也在增长
- 7.2 大矩阵怎样切到阵列上：分块（tiling）与权重的重新装载
- 7.3 小矩阵和不规则形状：边长不是阵列整数倍时的 padding 浪费
- 7.4 利用率曲线：阵列边长 × 矩阵形状 × batch 大小
- 7.5 一个大阵列还是几个小阵列：TPU v1 的 256×256，与后来 v2 到 v5 的 128×128（v4i 论文里的讨论），以及 Trillium 又回到 256×256
- 设计问题：为我们的芯片选一个阵列尺寸
- 实验：扫描阵列边长和矩阵形状，画出利用率热力图
- 配图：分块映射示意、利用率热力图

## 第三部分　一颗推理芯片（TPU v1）

### [第 8 章　喂饱阵列：片上存储](chapters/ch08_onchip_memory.md)

- 8.1 算一算：256×256 的阵列每拍要吃多少字节，DRAM 能给多少
- 8.2 Unified Buffer：一大块软件管理的 SRAM，存放激活值
- 8.3 Weight FIFO：权重从片外流进来，提前预取
- 8.4 双缓冲：阵列在算这一块的时候，下一块权重已经在路上
- 8.5 为什么不用 cache：访问模式完全可预测，软件管理更省面积也更确定
- 8.6 TPU v1 的瓶颈：DDR3 只有 34 GB/s，MLP 和 LSTM 在 roofline 上被带宽压住
- 设计问题：片上 SRAM 放多大，片外带宽要多少
- 实验：给模拟器加上片上缓冲和有限带宽的 DRAM，观察阵列在哪些模型上空等
- 配图：存储层次与数据通路、TPU v1 的 roofline（参考论文原图）

### [第 9 章　累加器与激活单元](chapters/ch09_accumulator.md)

- 9.1 部分和放在哪：阵列底部的累加器，为什么要单独一块存储
- 9.2 K 维分块后的累加：多次矩阵乘法的结果怎样加在一起
- 9.3 激活函数、池化和归一化：固定功能的硬件单元
- 9.4 重新量化：32 位累加结果怎样变回 8 位，送进下一层
- 设计问题：哪些运算值得做成硬件，哪些留给主机 CPU
- 实验：模拟器跑完一个两层 MLP 的前向，全程不回主机
- 配图：累加器与激活单元在数据通路中的位置

### [第 10 章　指令与控制](chapters/ch10_isa_control.md)

- 10.1 谁来指挥：TPU v1 是主机 CPU 的协处理器，通过 PCIe 接收指令
- 10.2 很少的几条大指令：读主机内存、读权重、矩阵乘、激活、写主机内存
- 10.3 CISC 还是 RISC：一条指令跑几千个周期，控制开销被摊薄
- 10.4 解耦访存与执行：读权重和做乘法并行推进，靠流水线和依赖检查衔接
- 10.5 去掉的东西：没有分支预测、没有乱序、没有 cache，控制逻辑只占很小的面积
- 设计问题：一颗芯片要多少"聪明"
- 实验：为模拟器定义一个小指令集，写一个汇编程序跑 MLP
- 配图：指令流水线示意、TPU v1 的芯片版图面积分布（参考论文）

### [第 11 章　拼成一颗芯片](chapters/ch11_tpu_v1.md)

- 11.1 整体框图：阵列、缓冲、累加器、激活、控制、PCIe、DRAM 接口
- 11.2 在模拟器上跑一个完整的推理：MLP、CNN、LSTM 各一个
- 11.3 对照论文：我们的估算与 TPU v1 实测（92 TOPS 峰值、相对 CPU/GPU 的每瓦性能）差在哪里
- 11.4 复盘第一代：哪些决策是对的，哪些是不得不做的妥协（带宽、只能推理、可编程性弱）
- 设计问题：如果再给一次机会，第一代芯片最该改什么
- 配图：完整芯片框图，并与论文框图并排对照

## 第四部分　走向训练（TPU v2 / v3 / v4i）

### [第 12 章　训练多了什么](chapters/ch12_training.md)

- 12.1 反向传播：每一层都要再做两次矩阵乘法，还要用到转置
- 12.2 激活值要留下来：显存需求一下子变大
- 12.3 精度：int8 训练不了，fp32 太贵，fp16 的动态范围不够
- 12.4 bfloat16：保留 fp32 的 8 位指数、砍掉尾数，乘法器小、转换简单
- 12.5 混合精度：bf16 相乘、fp32 累加
- 12.6 权重更新与优化器状态：这部分不是矩阵乘法，需要别的硬件
- 设计问题：为了训练，第一代芯片的哪些部件必须推翻
- 实验：在 NumPy 里用 bf16 模拟训练一个小网络，与 fp32、fp16 的收敛曲线对比
- 配图：fp32、fp16、bf16 的位格式对比

### [第 13 章　内存：从 DDR3 到 HBM](chapters/ch13_hbm.md)

- 13.1 训练的算术强度为什么更高也更低：batch 大了复用多，但优化器和逐元素运算是访存密集的
- 13.2 HBM：把 DRAM 堆叠起来放在芯片旁边，带宽提升一个数量级
- 13.3 新的存储层次：HBM、向量内存（VMEM）、寄存器
- 13.4 roofline 的移动：同一个模型在 v1 和 v2 上落在哪里
- 设计问题：带宽、容量、成本，三者如何取舍
- 配图：v1 与 v2 存储层次对比、两代芯片的 roofline 叠在一起

### [第 14 章　向量单元与标量核心](chapters/ch14_tensorcore.md)

- 14.1 矩阵之外的运算：激活、归一化、softmax、优化器，全都是逐元素或归约
- 14.2 从固定功能到可编程：向量单元（VPU）取代激活单元
- 14.3 标量核心和 VLIW：芯片自己取指、执行循环，不再每一步都靠主机
- 14.4 TensorCore 的结构：标量单元 + 向量单元 + 矩阵单元（MXU），以及多个 MXU 的组织
- 14.5 转置单元与数据重排
- 设计问题：把多少面积从矩阵单元挪给向量单元
- 实验：给模拟器加上向量单元，在芯片上跑完一个小网络的训练迭代
- 配图：TensorCore 内部结构、v1 到 v2 的芯片框图演变

### [第 15 章　编译器：硬件简单，软件就要聪明](chapters/ch15_compiler.md)

- 15.1 为什么 TPU 特别依赖编译器：没有 cache、没有乱序，调度全部要静态决定
- 15.2 XLA 做了什么：算子融合、分块、内存分配、指令调度
- 15.3 静态形状的代价与好处
- 15.4 手写 kernel：Pallas 让我们直接控制 VMEM 和 MXU
- 15.5 v4i 的教训：编译器兼容性、向后兼容、软硬件一起迭代
- 设计问题：一个新特性，放在硬件里做还是交给编译器
- 实验：为模拟器写一个极简"编译器"，把矩阵乘法自动分块并生成指令；在 Colab TPU 上用 Pallas 写一个矩阵乘法做对照
- 配图：从 JAX 程序到 TPU 指令的编译流程

## 第五部分　从一颗芯片到一万颗

### [第 16 章　片间互连](chapters/ch16_ici.md)

- 16.1 一个模型一颗芯片放不下：数据并行、模型并行、流水线并行
- 16.2 不走网卡，芯片之间直接连：ICI（Inter-Chip Interconnect）
- 16.3 拓扑：2D torus 和 3D torus，为什么环形连接对 all-reduce 友好

- 设计问题：每颗芯片留多少条链路、每条多宽
- 实验：用模拟器模拟一个 4×4 torus 上的 ring all-reduce，对比理论估算

### [第 18 章　Embedding 与 SparseCore](chapters/ch18_sparsecore.md)
