# 从零设计 TPU（学习笔记 / 写作计划）

边学边整理成一本书。整本书假装我们是一个从零开始的芯片团队：手上只有一个目标，**做一颗专门算神经网络的芯片**，然后一步一步做设计决策，直到把 TPU 的每个部件都"重新发明"一遍。

## 想法

讲 TPU 的资料不少，但大多是"介绍式"的：先给出一张架构图，再逐个解释 MXU、Unified Buffer、Accumulator 是什么。读完知道 TPU 长什么样，却不知道它为什么长这样。这本书换一个方向，从需求出发倒推设计。每一章都以一个具体的工程问题开头，例如"乘加单元放多少个才够""数据从哪里来才不会让乘法器空等""要支持训练，还缺什么"，先自己想方案、算代价，最后再对照 Google 实际的选择，看看自己的方案差在哪里、Google 又为什么那样取舍。

主线大致是这样一条路：从一个乘加单元（MAC）开始，把很多 MAC 排成网格，引出脉动阵列（systolic array）和数据流的选择；再给阵列配上片上缓冲、累加器、激活单元和指令，拼出一颗类似 TPU v1 的推理芯片；然后为了支持训练，引入 bfloat16、HBM、向量单元和标量核心，走到 TPU v2/v3；最后从一颗芯片扩展到成千上万颗，讲片间互连（ICI）、torus 拓扑、光交换（OCS）和 SparseCore，一直讲到最新一代的 Ironwood。

这本书和 [gpu_book](../gpu_book/) 是一对。gpu_book 问的是"在一块现成的通用芯片上，怎样把矩阵乘法写快"；这本书问的是"如果可以为矩阵乘法专门造一颗芯片，它应该长什么样"。两本书共用矩阵乘法、算术强度和 roofline 这套语言，GPU 和 TPU 的对比也会贯穿全书。

## 写作原则

- **先有问题，再有部件**：任何硬件结构都不直接给出，而是由一个算不动、喂不饱或者存不下的问题引出来。
- **每个决策都算账**：面积、功耗、带宽、峰值算力都尽量给出量级估算，让取舍有依据，而不只是"Google 是这么做的"。
- **能跑的模拟器贯穿全书**：用 Python 写一个逐周期（cycle-level）的小模拟器，从单个 PE 开始，随着章节不断长大。每加一个部件，都能跑一次矩阵乘法并统计利用率。条件允许时，再把核心模块用 Verilog 写出来，在 Verilator 上仿真。
- **对照真实设计**：每部分结尾对照 Google 公开的论文和文档，区分"已公开的事实"和"本书的推测"。
- **正文用 Markdown，配图用 drawio。**

本机是 Mac。Python 模拟器、Verilator 和 cocotb 都可以在本地运行；真正上 FPGA 需要开发板（可选）。想在真实 TPU 上跑 JAX/Pallas 做对照，可以用 Google Colab 或 Cloud TPU。
