## 0. 总评

这是一本底子很好、但还没收口的书。前八章已经达到出版水平，尤其第二、六、七、八、十一章；后六章和收尾部分还带着明显的草稿感。

它真正的护城河不是「手写 Transformer」，这个赛道很挤，而是三件事：

- **对拍**：每一章都和 `transformers` 对答案，判据随章节变化，并且每次变化都说明理由。
- **形状**：`(T, 576) → (T, 9, 64) → (T, 576)` 这样的形状链贯穿全书。
- **静默错误**：转置、字母序、`repeat`、eps、RoPE 起点，这些不报错但全错的坑，是全书最好看的暗线。

格式层面已经稳了：`check-prose` 和 `check-formulas` 全绿，章节图片没有死链。问题都在内容取舍、事实细节和收尾。

一个可操作的判断标准：凡是「有一个可运行的东西 + 一次对拍 + 一个不报错的坑」的章节，都好；凡是「介绍一个领域 / 回顾一遍」的章节，都弱。按这个标准，第九章后半、第十三章的逐章回顾、第十四章的 GPU 综述都该压。

## 1. 三个战略问题

### 1.1 书名承诺了一个「引擎」，书里交付的是「前向传播」

这是最大的战略问题，也是 `todo.md` 里 A1 一直悬着的原因。真正像「引擎」的只有第十一章（KV Cache、prefill/decode、内存账）和第十四章（设备、批处理）。其余十二章本质上是「手写一次前向 + 采样循环」。

两条路，选一条：

1. **补交付物**：最后给一个 `toyllm "..." --max-tokens 100 --temperature 0.8` 的命令行，带 KV Cache、流式输出、EOS 停止、多轮对话。`code/book/ch14/engine.py` 已经差不多了，差一层壳和一次演示。这样「引擎」二字就坐实了。
2. **改书名**：比如《自己动手写LLM推理》，副标题保留 *Build a Toy LLM Inference Engine*。英文里的 Toy 已经替中文挡了一层，但中文「引擎」仍会让读者按 vLLM 的预期买。

倾向第一条。它同时解决另一个问题：读完十二章，读者手里只有一个会续写的模型，情绪落点在第十三章才出现。

### 1.2 对拍是护城河，也是债务

「你不需要信我，跑一遍就知道」是全书最好的一句话，也是最脆弱的承诺。现在有三处没锁死：

- `code/download_model.sh` 用 `resolve/main`，HF 仓库一改，269,060,552、30,528、tokenizer 行号全变。
- torch 锁在 2.2（因为 Intel Mac），`transformers` / `tokenizers` 只锁大版本。
- 第十一、十三、十四章的耗时来自不同时间、不同负载的运行：42.5ms、48ms、45.0ms，prefill 153.4ms 和 141.2ms。读者会以为这是同一个引擎的同一个数。

建议：

- 前言或附录加一张「运行环境」表：Python、torch、transformers、tokenizers、模型 revision、机器型号。
- 下载脚本钉 commit，而不是 `main`。
- 正文明确「哪些数字是保证的，哪些只是我这台机器的观测」。
- 把第十一、十三、十四章的时间统一重跑一次，同一台机器、同一批次。

这比再写一章有用。

### 1.3 读者回报曲线

第四章到第十二章的输出都是胡话，这是题材决定的，不怪作者。第十章末尾那段 `Q: ... A: Paris.` 是个很好的小回报，但真正的对话在第十三章最后。

建议把 Instruct 对话提前到第十章末尾：引擎一行不改，只换权重、套 chat template，让「跑通」这一部分结束时读者手里有一个能对话的东西。第十三章就只负责「换模型」，不再承担唯一的情绪落点。这也是 `todo.md` 里 F14 的建议，值得执行。

## 2. 结构建议

### 2.1 第三章偏长

第三章 622 行，是全书最长。BPE 的 `model` 字段七个开关逐个讲，可以并成一张表；`added_tokens` 和 decoder 两节可压。目标 500 行左右。它是「分词」章，不该占全书十分之一。

### 2.2 第九章是两个半章

前半（残差流、逐层模长/余弦、跳层、logit lens）是全书最贴近推理的实验，很好。后半（HC/mHC/AttnRes）没有代码、不能对拍、动机全在训练稳定性，而且最容易过时，还违反前言「只解释 how」的约定。

建议降为「延伸阅读」或附录，最多保留 mHC 作为「残差流可以不止一条」的引子。Block AttnRes 那一段的描述还需要对照论文复核（见 4.9）。

### 2.3 第十三章六成篇幅是「这章不用改」

第二章到第十二章逐节报平安，节奏塌。把 ch4/5/8/9/10/12 压成一张「改了什么/没改什么」的表，把三个失败实验（head_dim 报错、QK-Norm 静默错、rope_theta 漂移）和最后的对话扩写。这一章的价值密度就是「三个 bug + 一场对话」，不是「十二章回顾」。

### 2.4 第十四章没有 CUDA 数据

5 处 `<!-- TODO CUDA -->` 是论点空缺，而唯一的实测是 MPS 比 CPU 慢近 5 倍，和「GPU 为什么快」的标题相反。没 CUDA 机器不是问题，拿 MPS 数据支撑 GPU 结论才是。

两条路：租一天 T4/A10 跑五个脚本，补完表和峰值显存；或者把章名改成「搬到另一个设备」，删掉所有「预期」表。
