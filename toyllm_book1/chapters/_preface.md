# 前言

聊天机器人、编程助手、智能体（Agent）……如今，大语言模型（Large Language Model，简称LLM）已经渗进了我们工作和生活的方方面面。我们每天都在和它们打交道：问一个问题，它一个字一个字地往外蹦答案，快的时候像是有人在对面打字，慢的时候也像是在“思考”。

用多了，难免会好奇：屏幕那头到底发生了什么？我们都听说过，LLM就是“预测下一个词”。可这句话说起来容易，真要追问下去就卡住了：一段文字是怎么变成数字送进模型的？模型里那几十层到底在算什么？算出来的又是什么，怎么就变成了下一个词？下一个词有了，再下一个呢？

这本书想用最直接的办法回答这些问题：**自己动手，从零写一个能跑的LLM推理引擎。** 我们会用Python和PyTorch，加载一个真实模型的权重，把一段文字切成词元（Token），送进三十层Transformer算一遍，采样出下一个词，再把它变回文字，然后循环。全程不使用`transformers`库里的模型实现代码，只有解析文件这两件杂活，分词和读权重，交给Hugging Face的`tokenizers`和`safetensors`两个库；其余的RMSNorm、RoPE、GQA、SwiGLU、KV缓存、采样、生成循环，统统自己写。

顺便说一句书名里的“推理”。它对应的英文是inference，意思是拿一个训练好的模型，给它输入，让它算出输出，和“训练”（training）相对。最近常听到的“推理模型”、“推理能力”，英文是reasoning，指的是模型在回答之前先想一想；为了不混，本书把后者叫作“思考”，第十三章会看到Qwen3的思考模式。两者不是一回事：本书写的推理引擎，不管模型会不会思考，都是按同样的步骤，一个词元一个词元地往下算。

我们的目标模型是**SmolLM2-135M**，可以跑在一台**普通笔记本的CPU**上。虽然有点慢，但每一个数字都能和Hugging Face的官方实现对上。等引擎写完，你会发现LLM并没有那么神秘：它就是一个装满了数的文件，加上一个按固定步骤读这些数、做乘法和加法的程序。

如果你也想亲眼看看这个程序是怎么一步步搭起来的，那就打开编辑器，我们一起开始吧。



## 写作动机

我是一名普通的程序员，此前写过三本和虚拟机有关的书，分别讲JVM、Lua和Wasm。写那几本书时，我用的都是同一个办法：想搞懂一门语言是怎么运行的，就自己动手写一个虚拟机，把字节码一条一条地解释执行。

后来重新学习AI，我在另一本书《人人能懂的人工神经网络》里，沿着历史脉络把神经网络从头梳理了一遍，从人工神经元一直讲到Transformer。可写完那些章节，我心里总觉得还差一点东西：原理我都知道了，可一个真实的模型到底是怎么跑起来的，我并没有亲眼“看见”过。于是那本书写到一半，我就先把它放下了，转而开始写“自己动手”这个系列，等这边告一段落，再回去把它写完。

再看一眼LLM，我忽然发现，它和虚拟机其实很像。模型文件就像是编译好的程序，里面装的不是指令，而是一亿多个浮点数；推理引擎就像是虚拟机，按照固定的步骤，把这些数读出来，和输入一起算。既然当年能靠写虚拟机搞懂一门语言，那么现在，也可以靠写一个推理引擎，搞懂一个LLM。这本书就是这么来的。

动手之前，我给自己定了一个方向，用一句话来概括就是：

> 从训练入手，会比较难；从推理入手，就比较简单，然后再去学训练。
>
> 从GPU入手，会比较难；从CPU入手，就比较简单，然后再去学GPU。

这两句话，后来也成了整个系列的路线图。本书是“自己动手”系列的第一本，先把推理写通；接下来的《自己动手训练LLM》、《自己动手写智能体》、《自己动手写深度学习框架》，分别去写训练、智能体和框架本身。另外还有两本书在构思中，一本讲GPU，一本讲TPU，专门回答“然后再去学GPU”之后的那些问题。



### 为什么是推理

“从零手写，理解LLM”这条路其实很挤：Karpathy的nanoGPT和llm.c，Raschka的《Build a Large Language Model (From Scratch)》（中译《从零构建大模型》），还有数不清的“手写Transformer”文章。它们都很好，但几乎全是**训练视角**：先搭一个模型，然后训练它。

从训练入手，你要同时面对四件事：模型结构、反向传播、数据和训练技巧，还有漫长的等待。四件事纠缠在一起，任何一个环节出了问题，都很难定位。

从推理入手，就只剩下一件事：**模型结构**。不用管梯度，前向传播就是一串矩阵乘法，每一步都能打印出来看；不用管数据，权重是现成的，别人已经训练好了；也不用等，改一行代码立刻就能看到结果。最关键的是，**每一步都能验证**。训练的时候，你很难判断自己写得对不对，损失在下降就算对吗？推理就不一样了，有`transformers`库当参照，你的输出和它要么对得上，要么就是哪里写错了。这本书的整个方法，就建立在这一点上。



### 为什么是CPU

同样的道理，GPU会带来一整套和“理解LLM”无关的麻烦：驱动、显存、CUDA版本，还有租卡。在真正理解模型结构之前，这些麻烦全都是噪音。CPU虽然慢，但慢得清清楚楚，而且135M的模型在CPU上跑一次前向只要几秒，做实验完全够用。

等理解了推理，再去学训练；等理解了CPU上的实现，再去看GPU上为什么要那么写，那时候两件事都会容易得多。本书最后一章会把同一个引擎搬到GPU上，量一量前面讲的那些道理；训练那条路，则留给下一本书《自己动手训练LLM》。



## 本书特色

和市面上讲LLM原理的书相比，我希望这本书能做到下面几点。



### 只看推理，不碰反向传播

这是全书的一条硬约定：**凡是要靠反向传播才能解释的问题，本书只给结论。** 比如“为什么需要残差连接”、“为什么pre-norm比post-norm好”，标准答案都藏在梯度里。遇到这种问题，本书会告诉你结论，以及它对推理代码有什么影响，比如pre-norm导致模型末尾必须多一个归一化，但不展开原因。想知道为什么，那是训练的事，也正是希望你之后再去学的东西。

唯一的例外是第九章。讲残差连接时，我们会破例聊一点梯度，不过只用乘方，不用求导，而且那一节整个可以跳过。



### 每写一个部件，就核对一次

书里每写完一个部件，我们都会拿它和`transformers`库算出来的结果比一比，看看数字对不对得上。你不需要相信我，跑一遍就知道。

能要求的精度是逐章变化的。前几章可以要求两边逐位相同，一个比特都不差；等第七章位置编码进来，就只能比相对误差了，第七章会专门解释为什么。到了第十章，又回到逐位相同，因为贪婪采样每一步都取最大的那个，一点点误差，就可能让后面生成的词全部变样。



### 盯住形状

这本书里的大多数bug，都不是数学错误，而是形状错误：转置了、维度顺序反了、reshape拼错了。这类错误有个共同的特点，就是**不报错**。代码照跑，输出也像模像样，只是全错。这也是上一条约定存在的理由。

所以正文里凡是有形状变化的地方，都会把前后的形状写出来，比如`(T, 576) → (T, 9, 64) → (T, 576)`。读的时候，不妨也跟着在心里算一算。



### 每章一个目录，代码能单独跑

本书的代码，每章一个目录，每一章都是从上一章复制过来再改的：

```
code/
  models/      模型权重，所有章节共享（很大，不入库）
  reference/   第一章生成的基准输出，所有章节共享
  book/
    ch01/
    ch02/      复制ch01，增量修改
    ...
    ch14/      最终形态
```

这样一来，**每一章的代码都能单独跑**。想看第五章那个“骨架搭好了，但还说不出人话”的状态，直接跑`ch05/`就行，不用去翻git历史。（我不想用git分支，感觉不好管理，读者上手也更麻烦。）代价是副本很多，改一处bug往往要改好几处，好在这是我的事，不是读者的事。



### 用真实的输出说话

书里出现的每一个数字，比如张量的个数、参数量、某个位置的分数、生成出来的那句话，都是实际跑代码得到的，正文里引用的输出，也都是原样贴过来的。你在自己的电脑上跑一遍，看到的应该和书上一样。



### 能画图的地方，就画出来

张量的形状、注意力的掩码、KV缓存怎么一格一格地填满，这些东西用文字讲半天，不如一张图看得明白。所以书里配了大量示意图，能列成表格对比的，也尽量列成表格。另外还有几个网页小工具，打开浏览器就能用，比如拖动两个向量，看RoPE旋转之后点积怎么变；或者给一个模型仓库名，看它的权重文件里每个张量排在哪里。读到相应的章节时，不妨打开玩一玩。



## 本书内容

和LLM相关的技术非常多，一本书不可能面面俱到。在这一节里，我会先说清楚本书写什么、不写什么，以及用到了哪些工具和模型；然后介绍整体结构和写作方式；最后说说这本书适合谁，以及怎么读效果更好。



### 主要内容

简单来说，本书只做一件事：把一个LLM的推理过程，从头到尾亲手写一遍。为了不让期望错位，先把边界划清楚。

**不是vLLM。** 我们的目标不是写出一个能上生产的推理引擎，而是理解LLM的工作原理，更准确地说，是理解它的推理过程。连续批处理、PagedAttention、分布式调度，这些都不在范围内，后记会提一句它们在解决什么。

**不讲训练。** 模型是怎么训练出来的，留给下一本书。

**不追求效率。** 能工作就行。例外是第十一、十二章和第十四章：KV缓存和FlashAttention本身就是性能问题，GPU更是为了快才用的，不谈性能就讲不清它们为什么存在。除此之外，全书一律选“看得懂”，而不是“跑得快”。

**只讲怎么做，不硬讲为什么。** 很多设计，比如SwiGLU为什么比ReLU好，连提出它的论文作者都说不清楚。遇到这种情况，本书会如实说明“它能工作，机理不明”，而不是硬编一个理由。



### 技术选型

编程语言选的是Python 3.12。AI相关，必须，没啥可说的。

框架选的是PyTorch 2.2。我们只用它的张量运算，比如矩阵乘法、广播、`nn.Linear`这类基础设施，不用它的任何高层封装。之所以选PyTorch而不是NumPy，是因为权重文件、参考实现、社区生态都在这边。至于为什么卡在2.2这个版本，是因为我的MacBook太老了，还是Intel芯片的，而PyTorch从2.3起，就不再发布macOS x86_64的安装包了。

模型选的是SmolLM2-135M。SmolLM2是Hugging Face在2024年10月放出的小模型系列，论文是《SmolLM2: When Smol Goes Big -- Data-Centric Training of a Small Language Model》（arXiv:2502.02737），有135M、360M、1.7B三个尺寸，**本书全程用最小的135M**。选它的理由有三条：

1. **架构是现代标配。** 它是Llama架构的Decoder-only模型（Hugging Face里就叫`LlamaForCausalLM`），RMSNorm、RoPE、GQA、SwiGLU、权重共享一样不缺。学会了它，Llama 3.2、Qwen 2.5这些主流模型的结构就都认识了。
2. **小到笔记本能跑。** 1.35亿个参数，权重文件269MB，全部升成FP32装进内存，也只有538MB，CPU上跑一次前向是秒级的。
3. **数字算得清。** 全书会反复手算参数量和张量形状，135M的每一个数都能心算验证。

和几个常见的小模型比一比：

| 模型             | 规模     | 架构世代                                  | CPU上          |
| ---------------- | -------- | ----------------------------------------- | -------------- |
| GPT-2 small      | 124M     | 旧（LayerNorm + 绝对位置编码 + 普通FFN）  | 能跑           |
| **SmolLM2-135M** | **135M** | **新**                                    | **能跑，秒级** |
| Llama 3.2-1B     | 1.24B    | 新                                        | 勉强，体感差   |
| Qwen2.5-1.5B     | 1.54B    | 新                                        | 勉强，体感差   |

后两个模型架构类似，但大了一个数量级，CPU上跑起来体感很差；GPT-2倒是够小，可它用的是LayerNorm、绝对位置编码和普通FFN，全是上一代的东西。SmolLM2-135M正好是“够现代”和“够小”的交点。

这个系列一共出过三代：2024年7月的SmolLM，2024年10月的SmolLM2，2025年7月的SmolLM3。之所以用第二代而不是最新的第三代，是因为SmolLM3只有3B一个尺寸，对本书来说有三处不合适：权重被切成了两个文件，第二章要讲的“一个文件、一段索引、一片浮点数”这个干净的结构就没了；它的`model_type`已经不是`llama`，每隔四层有一层不加位置编码，第七章要多讲一套东西；词表也涨到了128256，光一个词嵌入矩阵就有2.6亿个参数，差不多是整个SmolLM2-135M的两倍。

除了SmolLM2，第十三章还会换上Qwen3-0.6B，看看同一个引擎要改哪些地方才能跑另一个模型。第十四章的GPU数字，则来自Google Colab免费提供的T4显卡，不需要你自己买卡。



### 整体结构

全书十四章，分成三部分，后面还有一篇后记和四个附录。其中第一部分是“跑通”。我们沿着数据流从左走到右，每章造一个部件，到第十章，引擎就能生成文字了：

| 章   | 内容                                            |
| ---- | ----------------------------------------------- |
| 一   | LLM推理引擎概览：先用别人的引擎跑起来，看到终点 |
| 二   | 模型文件与权重：272个张量、134,515,008个参数    |
| 三   | 分词：全书唯一不碰权重的一章                    |
| 四   | 词嵌入：一个矩阵读两遍，得到一个零层的LLM       |
| 五   | 归一化：RMSNorm，以及pre-norm与post-norm        |
| 六   | 注意力机制：唯一让词元互相交换信息的部件        |
| 七   | 位置编码：补上RoPE，注意力才算完整              |
| 八   | 前馈网络：SwiGLU，顺带看一眼MoE                 |
| 九   | 残差连接：把两个子层包起来，Decoder块至此完整   |
| 十   | 采样：接上生成循环，引擎能用了                  |

第二部分是“跑快”。数据流不变，改的是执行方式：

| 章   | 内容                                              |
| ---- | ------------------------------------------------- |
| 十一 | KV缓存：prefill与decode，“引擎”二字从这里名副其实 |
| 十二 | FlashAttention：在线Softmax与分块                 |

第三部分是“走出去”。同一个引擎，换一个模型，再换一种硬件：

| 章   | 内容                                                   |
| ---- | ------------------------------------------------------ |
| 十三 | 换一个模型：用Qwen3-0.6B把全书回顾一遍，第一次和它对话 |
| 十四 | GPU：把第十一、十二章说的那些，在GPU上量出来           |

后记会聊聊量化、vLLM和llama.cpp，以及前面承诺过的“然后再去学训练”那条路。四个附录分别是矩阵相关的公式、引擎用到的全部公式、正文提到的论文和术语表，方便随时查阅。



### 写作方式

和《人人能懂的人工神经网络》一样，这本书也是我和AI一起写的，用的是Claude Code。具体的分工，不同部分不太一样：前八章是我自己写的初稿，再交给Claude润色；后面几章则反过来，由Claude按我定的思路写初稿，我逐段修改，再交给Claude润色一遍。随书代码则全部是Claude写的，我负责定方向、提要求、读代码、跑结果。

让AI帮忙写书，最容易让人担心的是代码：**AI写的代码，凭什么信？** 答案就是前面说的第二个特色：代码可不可信，不取决于是谁写的。这本书里每一章的实现，都要和`transformers`库核对，核对的脚本就在每一章的随书代码里。不是让你信我，也不是让你信AI，而是让你自己验。

某种意义上，这也是这本书能成立的前提：旁边有一个现成的、公认正确的参考实现，我们才敢说“从零手写”。如果你在阅读中偶尔读出一些“AI味道”，那大概就是这种写作方式的副作用，我会尽量把它改得更像人话。



### 目标读者

本书的目标读者，是**略懂AI、深度学习、神经网络和LLM，想再往里走一层，但一见到微积分和反向传播就想跳过的人**；或者，只是想从推理的角度，把LLM彻底搞明白的人。具体来说：

- **要会写代码。** 所以这本书不是给零基础的人看的。
- **可以不懂PyTorch。** 它只是工具，不是重点，用到什么讲什么。
- **可以不记得线性代数的细节。** 矩阵乘法和点积当作已知，其余用到时现讲，附录A也收了全书用到的矩阵公式。
- **不需要懂微积分和反向传播。** 全书用不到。

当然，也有一些读者不太适合这本书。如果你想学的是怎么训练或者微调一个模型，这本书帮不上太多忙；如果你要的是一个能上生产的推理服务，那应该直接去看vLLM、llama.cpp这些项目。不过，就算你已经很熟悉这些，用这本书把推理的每一步重新走一遍，或许也会有新的收获。



### 如何阅读

最好的读法，是**边读边跑**。每一章的代码目录里都有一个`README.md`，写清楚了这一章新增了哪些文件、怎么跑。建议先把代码跑起来，再往下读，书上的输出和你屏幕上的应该一模一样。

第一章会给出一张总览图，把整个推理流程画成四个盒子：Tokenizer、LLM、Sampler、Detokenizer。后面每一章都对应图上的一个框，章首会告诉你现在走到了哪里。另外，从第五章起，引擎每长出一样新东西，那一章的小结里就会写出一行当前的引擎形态，比如：

```
第五章  ids → embed → [norm → □ → norm → □] × 30 → norm → lm_head → logits
第八章  ids → embed → [norm → attn → norm → ffn] × 30 → norm → lm_head → logits
```

方框逐章填满。看着它一点点长大，比看架构图有用得多。

如果你对神经网络本身还比较陌生，比如不太清楚神经元、注意力、Transformer这些概念从哪里来，可以先读一读《人人能懂的人工神经网络》，再回来看这本书。如果读完这本书，你想知道这些权重是怎么训练出来的，那就接着读《自己动手训练LLM》，它会从零训练一个小模型，最后放到本书的引擎上跑。不过这两本书都还没有写完，已经写好的章节，可以在本书的GitHub仓库里找到。



### 提供反馈

不管你是刚开始接触LLM的新手，还是已经有不少经验的从业者，只要在阅读中发现了错误、疏漏，或者有更好的讲法，都非常欢迎告诉我。尤其是代码，如果你跑出来的数字和书上对不上，那很可能就是书里哪里写错了。

本书的书稿和随书代码都放在GitHub上，地址是<https://github.com/zxh0/vibe-writing/tree/main/toyllm_book1>，你可以在那里提交issue，与我交流。书稿是边写边公开的，没有“印完就定了”这回事：较小的笔误，看到就改；涉及内容和结构的调整，也会随着后面的修订慢慢更新进去。你的每一条反馈，都会让这本书变得更好。
