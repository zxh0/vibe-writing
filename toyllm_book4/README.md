# 自己动手写深度学习框架

Build a Toy PyTorch from Scratch

> 写作计划，书名待定。工作草稿，随讨论随时改。

## 想法

天天写`loss.backward()`和`optimizer.step()`，大致也知道背后是反向传播：链式法则，从输出往回一层一层乘。但“大致知道”和“亲手写过”差得很远。广播过的张量，梯度怎么缩回原来的形状？`x.T`为什么不复制数据，它的梯度又从哪来？`with torch.no_grad()`到底省了什么？就像toyllm系列的前两本，知道Transformer长什么样，不等于能写出推理引擎。所以这本书还是同一个办法：自己从零写一个玩具版的PyTorch，叫pytoych，一点一点来，每一步都看得见、跑得通。

市面上“从零写autograd”的材料已经很多（见[research.md](research.md)），这本书仍然按自己的思路写一遍。它和别的材料最大的不同，是处处和真的PyTorch对答案：API照抄PyTorch，每个算子的梯度都和torch比对，最后训出来的模型交给第一本的推理引擎去跑。

## 和其他几本书的关系

这本书是toyllm系列的第四本，补的是“框架”这一层：

* 《人人能懂的人工神经网络》讲清楚概念，把反向传播留到第十三章，只讲原理和推导，不写框架。
* 《自己动手写LLM推理引擎》（第一本）用PyTorch的张量和前向，手写了一个推理引擎。
* 《自己动手训练LLM》（第二本）用PyTorch的反向和优化器训练一个小模型，框架本身当黑盒。
* 《自己动手写智能体》（第三本）讲怎样把模型用起来，和本书没有直接的依赖。
* 这一本把第一、二本用到的那个黑盒拆开：张量、自动求导、模块、优化器、数据加载，全部自己写。

终点和第一本接上：用pytoych训练一个和第一本同样结构的小模型，导出成第一本引擎认识的模型目录，让它在第一本的引擎里生成文字。

这本书不要求读过其他几本。读过的话，第四部分讲嵌入、RMSNorm、RoPE、注意力的反向时，会对它们的前向很熟悉。

## 写作原则

* **一章一个概念。** 第三章就有一个能训练小网络的标量版自动求导，之后每章往上加一样东西：张量、广播、矩阵乘法、视图、模块、优化器……每加一样都能跑，都能和上一章比。
* **先有问题，再有部件。** 不直接介绍“`Module`是什么”，而是先让手写的训练脚本难看到受不了，再引出对应的设计。
* **处处对答案。** 和第一本每章比对`transformers`一样，这本书每章都和真的PyTorch比对。比对分几档，从严到松：
  * 前向和梯度用float64和torch逐个比，误差在舍入误差以内；
  * 用有限差分做梯度检查，不依赖torch也能验证；
  * 训练时用同样的初始权重、同样的数据顺序，pytoych和torch的损失曲线逐步对齐，误差标准每章说清楚。
* **API照抄PyTorch。** 名字、参数、默认值都和torch一致（`Tensor.backward()`、`nn.Module`、`optim.AdamW`、`DataLoader`）。同一份训练脚本，把`import torch`换成`import pytoych as torch`就能跑。照抄不了的地方，在正文里说明为什么。
* **对照PyTorch的真实设计。** 每章结尾看PyTorch在同一个问题上是怎么做的：`grad_fn`和`derivatives.yaml`、stride和视图、版本计数器、`no_grad`、AMP、`torch.compile`。区分官方文档写明的事实和本书读源码得出的推测。
* **只依赖NumPy。** pytoych本身只用NumPy做存储和计算，torch只作为对答案的参照出现在测试里。
* **正文用Markdown，配图用drawio。** 风格和toyllm系列前三本保持一致。

## 技术选择（待定）

下面几项还没定，先记下倾向：

* **语言和环境：** Python，uv管理，和前三本一致。作者的机器是2019款Intel MacBook Pro，所以torch钉在2.2.2、`numpy<2`，原因和第一本相同（见`toyllm_book1/code/CLAUDE.md`）。
* **后端：** 倾向于用NumPy做存储和计算内核，自动求导、模块、优化器、数据加载全部自己写。考虑过的另外两条路：纯Python的列表太慢，连MNIST都训练不动；自己写C内核会和gpu_book重复，范围失控。stride和视图那一章例外：先用纯Python实现一个迷你的Storage加stride讲清原理，再回到NumPy（NumPy的数组本身就是storage加stride，正好对照）。
* **精度：** 默认float32，和torch一致；梯度检查和逐位比对用float64。
* **终点模型：** 结构和第一本的SmolLM2一样（Llama风格：RMSNorm、RoPE、SwiGLU、GQA、权重共享），尺寸要小到NumPy在作者的Mac上几十分钟能训完，大概在百万参数的量级。数据和分词器倾向于直接复用第二本的（同一个数据子集、同一个词表），这样两本书训出来的模型可以对比。具体尺寸要等PoC测完速度再定。
* **导出格式：** 和第二本交给第一本的格式一样：一个模型目录，里面是`config.json`、`model.safetensors`和分词器文件。`safetensors`有NumPy接口，不需要torch。
* **记号（已定）：** 和toyllm第一、二本一致，用Goodfellow那一套：粗体小写表示向量，粗体大写表示矩阵。`.claude/lint-scope.json`里已经为本书关掉`符号记法/粗体大写`。
* **代码组织：** 沿用第一本的做法，`code/book/chNN/`每章一个自包含的目录，每章在上一章的基础上改。pytoych是其中的一个包，测试和对答案的脚本放在旁边。
* **不做的：** GPU和CUDA（指向gpu_book）、卷积和循环网络（终点是语言模型，用不上；ann_book讲过概念）、分布式训练、高阶导数（只在正文里提一句）、静态图和编译（最后一章只讲思路，不实现）。

## 要先用PoC回答的问题

和第二本一样，动笔之前先写一个PoC，回答几个会影响大纲的问题：

* **P0 速度：** 用NumPy在作者的Mac上训练一个百万参数的Llama风格模型，每秒能处理多少token？这决定终点模型的尺寸、数据量，甚至第四部分还能不能成立。
* **P1 对齐：** 同样的初始权重和数据顺序，pytoych和torch的损失曲线在float32下能对齐到什么程度？float64呢？这决定“处处对答案”的标准写到多严。
* **P2 接口：** 导出的模型目录能不能不改一行代码就被第一本的引擎加载、生成文字？
